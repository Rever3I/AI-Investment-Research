# 价值投资股票分析 Pro 版本

按对冲基金的投研流程搭建，从选股到建仓五段闭环。财报直连 SEC 官方申报数据，
不预测涨跌，只算这门生意值多少钱、以及当前价格已经替你假设了什么。

## 五个阶段分别给你什么

| 阶段 | 产出 |
| --- | --- |
| 发现 | 一份候选名单，每个附一句入选理由。可以按你的条件筛，也可以从你已有的一个判断反推 |
| 研究 | 一份完整研究报告：生意、管理层、竞争格局、市场空间、8-12 条风险，以及什么情况下这个判断就是错的 |
| 估值 | 股东盈余 DCF、反向 DCF，外加一个可拖动的交互式 HTML 页面 |
| 仓位 | 按你给的情景概率算出建议权重，默认半 Kelly |
| 复查 | 想卖的时候，把当初写下的判断调出来做对账 |

## 一次真实运行

可口可乐，数字全部实时取自 SEC EDGAR：

```
股东盈余      $12.0B      净利润 + 折旧摊销 - 资本开支，FY2025 10-K
股本          43.1 亿股   CommonStockSharesOutstanding
股价          $86.84      Yahoo 行情，已通过时效校验

反向 DCF      19.7%       当前价格已经隐含的年复合增速
                          折现率 9.2%，永续增长 2.6%

情景估值      乐观 $54.24   中性 $47.96   悲观 $40.61
半 Kelly      0.00%       这个价格上没有边际
```

先看反向 DCF 这一行。它把「可口可乐现在贵不贵」换成了一个你自己能回答的问题：
一家软饮公司，未来十年能不能每年把股东盈余复合 19.7%。后面的情景估值和仓位建议，
用的是你自己填的增长率假设。

上面每一个数字都带着来源、单位和数据时点。过期数据会直接中断这次运行，
不会悄悄混进报告里继续用。

## 交互式估值页面

每次估值会生成一个自包含的 HTML 文件。拖动折现率或永续增长率，
所有情景在浏览器里当场重算。没有 CDN、没有外部字体、没有任何网络请求，
所以几年后在一台断网的机器上打开，它照样能跑。

页面第一次打开时显示的是保存下来的那组数字，并且会标明这一点；你动过任何一个
参数之后，它会标记为「已重算」。某个情景如果自带折现率，你调全局折现率时它不受影响，
悲观情景不会在你手底下悄悄变成中性情景。

页面还会给出每个情景的永续价值占比：估值里有多少来自永续假设，多少来自明确预测的那几年。
一个 85% 价值来自永续段的估值，说的更多是折现率，而不是这门生意，这件事应该看得见。

## 数据为什么可信

直接读 XBRL 会得到一批看起来完全正常、实际是错的数字。下面是实盘跑真实申报文件时
撞到的案例，每一条现在都有对应的规则拦着：

| 公司 | 直接读的结果 | 实际 | 原因 |
| --- | --- | --- | --- |
| Simon Property | 13.0 亿股 | 3.24 亿股 | 加权平均股本按期间条目申报，四个季度被加了起来 |
| 麦当劳 | 716 股 | 7.08 亿股 | 这项数据以「百万」为单位申报 |
| 星巴克 | 折旧摊销 $362M | $1.77B | 一个更新的单季数据压过了年度数据，公司随即显示为没有股东盈余 |
| 壳牌（伦敦） | $3,356 | 约 $45 | 伦敦报价单位是便士，却被标成了美元 |
| 英伟达 | 资本开支停在 2020 年 | 当期 | 公司 2020 年前用的旧标签一直压过现在在用的那个 |

这些数字没有一个通不过直觉检查。四个季度加出来的股本，仍然是个合理的股本；
一个季度的折旧，仍然是个合理的折旧。只能靠规则拦：存量指标永不求和、
期间按实际天数过滤、报价必须带币种、超过时效上限的数据直接拒绝。

## 它拒绝做什么

拒绝在这里是功能的一部分。下面每一种情况，硬算都会得到一个看起来很确定、
实际没有意义的数字。

- **银行和 REIT。** 它们常常没有资本开支这一行，而股东盈余 = 净利润 + 折旧摊销 - 资本开支。
  缺失项会被当成零，恰好把资本开支最要命的那类生意美化了。它会直接说这个方法不适用，
  而不是把缺口填上。
- **亏损公司。** 对负的股东盈余做 DCF，会得到一个负的目标价，配一个看起来很正常的
  永续占比——那是两个负数相除的结果。
- **非美元报价。** 伦敦、东京上市的标的会被拒绝，而不是当成美元处理。
- **外国私人发行人。** 它们按 IFRS 申报，这套工具读不了，会明说这一点，
  而不是让你以为代码敲错了。
- **没有边际的仓位。** 当期望收益在当前价格下不为正，Kelly 给出 0。
  这是算式在拒绝下注，不是缺一个答案。

## 配置

行情源零配置就能跑。两个可选的 key 打开其余部分：

```json
{
  "sec_contact": "Your Name you@example.com",
  "fred_api_key": "",
  "output_language": "zh-CN",
  "sizing_method": "half_kelly",
  "position_cap": 1.0
}
```

- `sec_contact` —— SEC 要求 User-Agent 里带联系方式，不填会返回 403，美股财报就没有数据源。
- `fred_api_key` —— 圣路易斯联储免费申请，用来给折现率提供有出处的无风险利率。
- `output_language` —— 研报用什么语言写。填 `zh-CN` 出中文报告，语言标签不设白名单。
  程序自身的日志和报错保持英文，方便搜索排查。

任何时候跑一次 `status_report(configure())`，会列出哪些数据源现在能用、
缺的是哪一项设置。

## 数据源

| 领域 | 数据源 | 需要什么 |
| --- | --- | --- |
| 行情 | Yahoo（两个 host），再退到 Stooq | 无 |
| 美股财报 | SEC EDGAR XBRL | `sec_contact` |
| 宏观 | FRED | 免费 key |
| 中国上市公司 | Wind | 已授权的终端 |

每个领域是一条链。主源失败会自动试下一个，并把这次降级记进日志——
一个悄悄一直失败的主源，从外面看和正常工作的一模一样。

## 使用场景

**在推特上看到一个票，想知道值不值得花时间。** 直接进研究阶段，先看反向 DCF。
如果价格已经假设了未来十年 40% 的增速，你不用建模就有答案了。

**手上有一个宏观判断，但不知道买什么。** 从判断出发，发现阶段会顺着这个逻辑
推到产业链上真正能表达它的公司。

**已经赚了 60%，在犹豫要不要减。** 复查阶段调出你当初写下的理由，
把变化分成三类：事实变了、判断变了、依然成立。这三种情况该做的事完全不同，
但在一个正在赚钱的仓位里，它们的感觉是一样的。

**已经决定要买，只想定个仓位。** 给它你的情景概率，它返回半 Kelly 结果，
并把输入参数一起存下来，将来这个数字是可以被回溯质疑的。

## 常见问题

**它会告诉我买什么吗？**
不会。它呈现的是价格假设了什么、数据支持什么、什么情况下这个判断会被证伪。
每个阶段都停在给建议之前。

**它预测股价吗？**
不预测。反向 DCF 报出的是当前价格隐含的增速，这是对市场假设的一个描述。

**数据有多新？**
年度数据取自最近一份 10-K，季度数据取自已申报的季度，行情取最近一个正常交易时段的收盘价。
任何超过时效上限的数据会中断运行，不会被拿来用。

**能用在 A 股上吗？**
Wind 适配器按 Wind 官方文档的接口写成，但**没有在真实终端上验证过**——
WindPy 随付费产品分发，无法单独安装。请把它当作起点。

**我不同意它算出来的估值怎么办？**
你本来就应该能不同意。增长率和概率是你填的，折现率没有默认值、必须带来源提供，
交互式页面存在的意义就是让你把假设拖一拖，看答案怎么变。

**需要联网吗？**
取数需要。生成出来的估值页面之后可以离线打开。

## 已知边界

- 股东盈余 DCF 适合有稳定盈利、资本开支可辨认的生意。银行、保险、早期公司和
  很多 REIT 都不适用，遇到这些它会说不适用，而不是硬给一个数字。
- 可保存的筛选 profile 设计已定、尚未实现，发现阶段目前跑的是通用搜索。
- Wind 适配器未经真实终端验证。
- 以上内容不构成投资建议。
